# インスタ部門 Next.js版の引き継ぎ

更新: 2026-11-26。コードと検証結果を渡すための資料です。既存GASの運用は継続し、本番切替は行っていません。

## 確認用コードと申請順

公開の確認用リポジトリ: https://github.com/smitch-ai-works/aione-instagram-portal-review （main）

この公開版は、私有設定・認証情報・実データ・内部の申請文と旧開発履歴を含めない、検査済みコードのスナップショットです。既存の開発リポジトリは非公開で保持します。運営リポジトリの発行やデプロイが完了したことを意味しません。

今回は、上記の既存リポジトリのコードを指定して「ONEのツールとして登録」を依頼します。新しい空のリポジトリ発行を前提にはしません。運営側でコードの取り込みや管理先の変更が必要な場合も、この実装を引き継ぎます。

Chatworkでは、11月3日のaione-webinarで、既存リポジトリのPR #1を指定した初期デプロイ依頼を確認しました。新規発行・招待を先に行う事例もありますが、それだけを唯一の方法と判断しません。個人アカウントのリポジトリを直接運営登録した完全に同じ事例は、閲覧可能な範囲では未確認です。

## 実装とデータの流れ

```text
同じスプレッドシート
  → Next.jsサーバー（取得・名寄せ・重複除外・集計・判定）
  → 画面／月報ログ保存／LINE通知の処理
```

4画面、NG設定、月報ログ15列、通知5種類、定期更新の実装を移植済みです。Next.jsの稼働時にGASへ処理を依頼しません。旧GASへ接続するツールは移行元との比較専用です。

標準の画面再取得は60秒とタブ復帰時、サーバー読取キャッシュは30秒です。スプシの変更は次の再取得時に反映されます。

## Google接続の現状と残る設定

利用者ごとのGoogleログインは不要です。認証はNext.jsサーバーがGoogle APIへ接続するためのものです。

- 読取: 既存の共有状態で利用できるExcelエクスポートと、認証済みSheets APIの両方で最新の実データを現行GASと照合済みです。API経路の全体照合はローカルで約32秒でした。配置先の取得時間は別途確認します。
- 月報保存: 既存の許可済みアカウントを用いたGoogle ADCで実保存・重複防止・復旧を確認済みです。
- 継続運用: 現在の資格情報は外部テストモードの受入用です。7日期限の対象なので、これを本番の常設認証としてそのまま渡す構成にはしません。配置先の実行主体・運用用OAuth設定を確定してから再接続を確認します。
- サービスアカウント: GoogleAuthは対応しますが、実スプシの共有追加・実接続は未実施です。保存先の共有検査は元GASと同じ許可一覧を使います。追加共有だけを行うと旧GASの保存が拒否される可能性があるため、旧GASを変更しない今回の工程では追加しません。

認証なしで非公開スプシへ書き込む機構は使いません。Google認証の設定変更、共有主体の変更、運営の認証基盤への接続は、コードの公開とは別の作業です。

## 配置担当者に必要な設定

[DEPLOYMENT.md](DEPLOYMENT.md) と [.env.example](../.env.example) が設定の入口です。

1. Node.js 22以上、Next.jsのサーバー実行、`NEXT_PUBLIC_BASE_PATH=/aione-instagram` を用意する。
2. 画面・APIの両方を、ONEログインとインスタ部門の利用権限の内側へ配置する。管理者PWはNG設定編集用で、全画面の閲覧制限の代わりではありません。
3. 管理設定・月報の保存履歴・通知履歴に永続領域を用意する。現在は単一ホストのJSONファイルとプロセス間ロックを前提とします。複数ホスト・サーバーレスの一時ファイルにはそのまま置かず、共有トランザクションストアへ置換します。
4. ソース設定、月報の許可一覧、Google資格情報、LINE資格情報、管理者PWハッシュ等を秘密管理領域へ登録する。公開リポジトリには含めません。
5. 実データ量での読取方式・初回取得時間を確認する。取得失敗を0件・0円として表示しない仕様を保つ。
6. 実機iPhone/Android・LINE内ブラウザのコピー・PNG保存を確認する。PC上のモバイル幅の検査とは別です。

`PORTAL_NATIVE_START_MONTH=2026-11` は固定値です。配置月に合わせて進めません。

### 安全なテスト環境の条件

`PORTAL_JOBS_ENABLED=false`、`PORTAL_JOB_OWNER=gas` を維持し、通知ワーカーや定期更新の実適用を開始しません。`deployment/schedules.example.json` は実時刻を確定した記録ではありません。

月報ログへの書込みを確認する場合は、対象とテスト記録を決め、同一UUIDの重複防止から後片付け・既存行の照合まで行います。テスト配置だけで一般利用者へ開放しません。

## コードだけを確認する手順

```sh
npm ci
npm test
npm run build

node tools/check-publication-safety.mjs --history
```

秘密設定がない環境でも単体・模擬APIのブラウザ検査は可能です。Google実接続には上記の私有設定が別途必要です。実データによる照合と模擬テストを区別してください。

一回限りの再インポートを行う場合、`tools/prepare-native-migration.mjs` のリンク元ID・対象外名・限定リンク対象者は `PORTAL_MIGRATION_CONFIG_FILE` または既存の私有 `.local/source-config.json` から読みます。通知インポートの収益対象外名は `PORTAL_NOTIFICATION_IMPORT_CONFIG_FILE` または既存の私有 `.local/notification-config.json` から読みます。初回はこれらの私有設定を用意し、個人名や識別子をコードへ書き戻しません。

通知の仕様は [NOTIFICATIONS.md](NOTIFICATIONS.md)、保存の仕様は [MONTHLY_OUTPUT.md](MONTHLY_OUTPUT.md)、実装範囲は [MIGRATION_INVENTORY.md](MIGRATION_INVENTORY.md) を参照してください。

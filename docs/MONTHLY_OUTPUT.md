# 現行GAS v11に合わせた月報ログ保存

2026-11-22の本人指示で、稼働中のGASを正本として移植した。GAS・デプロイ・共有権限・元シートは変更しない。Next.jsはGoogle APIへ直接接続し、GASを呼ばずに保存する。

## 動作

「月報作成 → 全文コピー → オプチャでアウトプットする」の順序は維持する。アウトプットを押すと、元GASと同じ案内と保存処理が動き、オプチャへのリンクも通常通り開く。LINE本文の貼付・送信は本人が行う。保存失敗はLINEへの投稿とは別の状態として案内し、同じIDで保存を再試行できる。

保存する15列は、対象月・日本時間の投稿日・氏名・リスト数・収益・リール・フィード・ストーリーズ・前月末/当月末フォロワー・増減・4つの振り返り。実績はブラウザから信用せず、同じスプシのサーバー読取で確認する。入力欄の原文とは別に、ログには元GASと同じNG除外後の文を保存する。明示的な0と空欄、不正項目・対象月を区別する。

## 私有設定と認証

- `PORTAL_MONTHLY_OUTPUT_CONFIG_FILE`: 絶対パス。現行GASの `MONTHLY_OUTPUT_` の `id/gid/tab/headers/fields/counts/key`、共有主体のハッシュをキーにした `approvedRoles`、`enabled:true` を持つJSON。主体・ハッシュをGitや依頼文へ記録しない。
- `PORTAL_MONTHLY_OUTPUT_STATE_FILE`: 絶対パス。ロック・回数制限・保存済みIDを保持する1ホストの永続ストア。初期JSONは `{"settings":{"revision":0,"words":[]},"sessions":{},"saved":{}}`。公開領域・一時領域に置かない。複数ホストでは共有トランザクションストアへ置換する。
- Google ADC: `spreadsheets` 書込と `drive.metadata.readonly` のスコープが必要。現行GASの許可済み主体・役割に一致し、保存先の `canShare` を確認できる実行IDを用意する。接続の迂回策として別の共有主体を追加したり、許可一覧・共有権限を緩めたりしない。必要な権限変更は別途本人へ確認する。

ローカルのユーザー認証には、運営側が管理する専用のデスクトップOAuthクライアントを使う。clasp既定クライアントにSheets/Drive権限を追加する流用方式は、11/23の確認でGoogleにブロックされたため使わない。Google公式もGoogle Cloud外のAPI用スコープには独自OAuthクライアントの指定を案内している（[ADCのローカル開発設定](https://docs.cloud.google.com/docs/authentication/set-up-adc-local-dev-environment)）。専用クライアントの秘密情報・発行後のユーザー資格情報は私有領域だけに保存する。

現行ソースを私有ディレクトリへ読取取得後、`node tools/import-monthly-output.mjs <私有ディレクトリ>` で純粋処理・クライアント処理・私有設定を移せる。GASやGoogleファイルへは書き込まない。Next.js固有の画面の自動再取得は保持する。

設定・永続ストア・認証・共有検査が利用できなければ、初期化の `monthlyOutputEnabled` はfalseになる。設定ファイルを用意しただけで書込認証が整ったと判断しない。

## サービスアカウントへ変える場合の互換性

GoogleAuth自体はサービスアカウントに対応するが、実シートへの接続は未検証。元GASの共有検査も同じ個別許可一覧を使うため、新しいサービスアカウントを編集者として追加するだけでは、元GAS側の保存が拒否される可能性がある。今回の「既存GASをそのまま残す」工程で、共有主体やGASの許可一覧は変更しない。検証済みの接続は既存の許可済みアカウントを使ったサーバー側ADCであり、利用者ごとのGoogleログインは不要。

継続運用用のOAuth設定・実行主体・秘密管理を配置先に合わせて確定し、現在の7日期限のテスト資格情報をそのまま本番用にしない。サービスアカウントを採用する場合は、新旧双方への影響と必要な許可設定を別途確認してから実接続・復旧まで受け入れる。

## 検査と二重保存防止

1. 個別共有の主体・役割を元GASと同じ許可一覧で検査する。検索公開されないリンク閲覧は許し、リンク編集・検索公開・未登録共有・公開ビュー・権限変更中などを拒否する。共有ドライブ・ゴミ箱・別ファイルも拒否する。
2. UUID、対象月・氏名、サーバーで取得した実績、振り返り・任意数値を検証する。1分30件とプロセス間ロックを維持する。元の日本語各欄3,000文字を保つため、このRPCのみ最大64KB、それ以外は16KBとする。
3. タブ名・ID・15列のヘッダーを一致確認し、追記直前に共有検査を再実行する。共有ACLはキャッシュしない。
4. Sheets `batchUpdate` の1バッチに、リテラル文字列でのセル追記とUUIDのハッシュをDeveloperMetadataへ記録する操作をまとめる。数式として実行される値は送らず、POSTの自動再試行を無効にする。
5. 同じUUIDの再試行・同時要求・通常再起動後は、永続ストアとGoogle側のマーカーで保存済みを判定する。結果不明時も新しいUUIDへ変えず同じIDで照合する。元GASと同じPROJECTメタデータはGoogleプロジェクト単位のため、運用中に実行プロジェクトや永続ストアを不用意に入れ替えない。

## 検証と本番受入

`node tools/check-monthly-output-parity.mjs <私有の現行ソースディレクトリ>` は、架空データで元GASの純粋処理と比較し、Googleファイルを変更しない。単体・ブラウザテストもGoogle APIを模擬する。

11/22に本人がテスト書込みと原状復帰を承認し、11/23に専用アプリへのSheets編集とDriveメタデータ読取の許可操作も承認。専用プロジェクト・Sheets/Drive API・デスクトップOAuthクライアントを設定し、本人アカウント1人だけをテスト対象としてGoogle認証を完了した。資格情報はGit除外の私有領域だけに保存し、元のclasp認証を保持している。

受入では既存行のハッシュとシート形状を先に記録し、Next.jsのRPCから識別可能なテストを1件保存する。同一UUIDの再試行で1件のままであることをGoogle側から読み取り、今回のセル値・DeveloperMetadata・ローカル保存済みマーカーだけを除去する。既存の検証記録や同時に入った通常の投稿を削除せず、既存行・件数・形状を再確認する。認証や保存が失敗した場合も、この後片付けを完了するまでは受入完了としない。運営環境の認証・永続領域と本番切替は別途残る。

11/23の実施結果: Next.jsの実RPCで1件保存し、別のSheets API読取で15列の一致を確認。同じUUIDの再送で行・マーカーとも1件を維持した。今回のテスト記録を除去した後、ログは83件→84件→83件に戻り、ヘッダーと既存83件のハッシュ・シート形状が開始時と一致した。Googleとローカルの今回のマーカーは0件。既存GAS・共有権限・LINE配信は変更していない。

今回のユーザー認証は検証用の外部テストモードであり、更新トークンは7日で期限切れになる。[Googleのトークン有効期限](https://developers.google.com/identity/protocols/oauth2#expiration)に従い、本番運用の認証は別途整備する。今回の機能再現・保存と復旧のテスト完了と、常時運用への切替を混同しない。
